# Notion-Updater — крипта на websocket-ценах (дизайн)

Дата: 2026-10-03

## Цель

Убрать постоянный опрос CoinGecko из модуля крипты. Цены получать push-потоком
(websocket) и писать в Notion по расписанию, минимизируя число запросов к Notion.

## Проблема

`updaters/crypto.py` каждые `CRYPTO_UPDATE_SECONDS` делает HTTP-запрос к CoinGecko
`/coins/markets` (с fallback на `/coins/{id}`). С датацентровых IP CoinGecko часто
отвечает `403`/`429`, и обновление цен срывается. Плюс каждый цикл — новые запросы
к провайдеру.

## Ключевые решения

1. **Push вместо опроса.** Долгоживущее websocket-соединение; цены приходят сами.
2. **Провайдеры:** Kraken (основной) + Coinbase (fallback). Оба — публичные стримы
   без API-ключа, дружелюбны к облакам/US-региону. Binance/Bybit/OKX исключены:
   блокируют US-IP либо запрещены в ряде юрисдикций. CoinGecko бесплатного WS не даёт.
3. **«Без танцев» при добавлении монеты.** Сервис раз в `CRYPTO_RESYNC_SECONDS`
   перечитывает базу Notion и подписывается на новые монеты автоматически.
   Правок кода/конфига не требуется.
4. **Формат `Symbol` гибкий.** Понимаем биржевую пару (`BTC-USD`, `XBT/USD`),
   голый тикер (`BTC`) и CoinGecko-id (`bitcoin`, резолвится лениво).
5. **Минимум запросов к Notion.** Пишем `PATCH` только по изменившимся ценам;
   список страниц кэшируем; базу читаем 1 раз в 5 минут.
6. **Свежесть ≤ 30с.** Тик записи — каждые 30 секунд (не чаще 20с, настраиваемо).
7. **Архитектура — вариант 1:** фоновый поток на стрим + существующий APScheduler.
   Весь I/O приложения синхронный; asyncio не вводим.

## Архитектура и раскладка

Новый пакет `prices/` — провайдеро-независимый слой рыночных данных:

| Файл | Ответственность |
|---|---|
| `prices/models.py` | `CoinSpec` (страница, исходное значение, разрешённая пара), `PricePoint` (цена, вчера, время тика) |
| `prices/providers.py` | Интерфейс `Provider` + `KrakenProvider`, `CoinbaseProvider`: `ws_url`, формат подписки, разбор сообщения, `format_pair` |
| `prices/symbols.py` | Разрешение значения из Notion → биржевая пара; ленивый CoinGecko `/coins/list` с кэшем; алиасы Kraken; fallback USD→USDT |
| `prices/engine.py` | `PriceEngine`: поток, соединения, подписки, переподключение, потокобезопасный кэш, `snapshot()` |

Изменения в существующем коде:

- `updaters/crypto.py` — тонкий «писатель». Предоставляет `CryptoUpdater`,
  инкапсулирующий движок, кэш страниц и последние записанные значения; методы
  `write_tick()` и `resync()` вызываются задачами планировщика. Движок создаётся в
  `main.py` и передаётся в `CryptoUpdater`/`build_scheduler`. HTTP-код CoinGecko
  (`_fetch_markets`, `_fetch_per_coin`, `fetch_prices_from_coingecko`,
  `compute_yesterday_price`) удаляется.
- `main.py` — создаёт, запускает `PriceEngine`, останавливает при завершении.
- `scheduler.py` — крипта: две задачи на общем движке — `crypto_write` (30с) и
  `crypto_resync` (5 мин).
- `config.py` — новые поля `CryptoConfig`.
- `requirements.txt` — `websocket-client`.

Слои изолированы: `prices/` тестируется без сети и Notion; `updaters/crypto.py`
знает только про Notion. Общий клиент `notion.py` не меняется.

## Поток данных и жизненный цикл

**Старт:** `load_config()` → создаём `PriceEngine` (провайдеры по приоритету) →
запускаем поток (без монет) → немедленный `resync` (читаем базу, разрешаем символы,
`engine.ensure_coins(...)`) → старт APScheduler.

**Движок (фоновый поток):** подключается к Kraken, подписывается на пары, на каждое
сообщение обновляет `{пара → PricePoint}`. Монета, которой нет на Kraken → уходит на
Coinbase. `ensure_coins` на лету до-подписывает новые и отписывает удалённые.

**Запись (`crypto_write`, каждые 30с):** `snapshot()` → для каждой страницы сравнение
с последними записанными `price`/`yesterday` → изменилось → один `PATCH`
(`price` + `Last Updated` [+ `yesterday`]); не изменилось → пропуск.

**Resync (`crypto_resync`, каждые 5 мин):** перечитываем базу, обновляем кэш страниц,
диффим набор монет, добавляем/убираем подписки.

**Стоп:** SIGTERM/SIGINT → закрываем соединения и поток движка → `scheduler.shutdown`.

## Разрешение символа

Значение из `Symbol` нормализуется по шагам, первый успешный выигрывает:

1. **Явная пара** (`BTC-USD`, `XBT/USD`, `BTC-USDT`) → используем как есть, приводим
   к формату провайдера.
2. **Голый тикер** (`BTC`, `ETH`, `SOL`) → `TICKER/USD` у Kraken, затем `TICKER-USD`
   у Coinbase; если пары нет — `TICKER/USDT`.
3. **Похоже на CoinGecko-id** (`bitcoin`, `solana`; строчные, не тикер) → ленивый
   `GET /coins/list` (один запрос, все пары id↔symbol), кэш в памяти, берём тикер →
   шаг 2.
4. **Не разрешилось** → warning с понятным текстом, монета пропускается, повтор на
   следующем resync.

Кэш разрешений: не пересчитываем на каждом тике. Алиасы Kraken (`BTC→XBT`,
`DOGE→XDG` и т.п.) — таблица в `KrakenProvider`. Формат пары задаёт
`Provider.format_pair(base, quote)`: Kraken → `XBT/USD`, Coinbase → `BTC-USD`.

Рантайм-эффект: добавил строку `SOL` или `solana` → следующий resync (≤5 мин)
подписал → цена пошла.

## Минимизация запросов к Notion

На страницу храним: `page_id`, разрешённую пару, последние записанные `price`/`yesterday`.

На тике для каждой подписанной монеты:

- **Свежесть:** если тик старше `CRYPTO_STALE_SECONDS` — не пишем, warning
  (не заливаем устаревшее).
- **Дедуп:** `price` и `yesterday` сравниваются с последними записанными; при
  равенстве (epsilon против шума float) запрос не делается.
- **Изменилось** → один `PATCH`: `price` + `yesterday` (если есть) + `Last Updated`,
  равное времени фактической записи.
- **Пульс:** при `CRYPTO_HEARTBEAT_SECONDS > 0` и отсутствии изменений дольше N минут —
  `PATCH` только `Last Updated`. По умолчанию `0` (выключен).

Итог: число запросов ≈ число монет с реально изменившейся ценой, не чаще раза в 30с.
Чтение базы — 1 запрос на 5 минут.

## Обработка ошибок

- **Обрыв WS:** переподключение с экспоненциальным backoff + jitter (1→2→4…→max 60с).
  После реконнекта — повторная подписка на актуальный набор. Таймаут отсутствия
  сообщений → соединение считается мёртвым, переподключаемся.
- **Изоляция провайдеров:** падение Kraken не трогает Coinbase; монета уходит на
  fallback, если её нет у основного.
- **Кривые/неизвестные сообщения** — `debug`-лог, поток не падает.
- **Ошибка `PATCH` по странице** — `try/except`, лог, повтор на следующем тике;
  остальные страницы пишутся.
- **Поток движка устойчив:** внешний `try/except`; падение внутри не роняет процесс.
- **Старт:** база недоступна → лог, повтор на resync. Монет нет → движок простаивает.

## Конфигурация

Новые переменные (все опциональны, с дефолтами):

| Переменная | Дефолт | Назначение |
|---|---|---|
| `CRYPTO_TICK_SECONDS` | `30` | интервал записи (значения < 20 зажимаются до 20) |
| `CRYPTO_RESYNC_SECONDS` | `300` | период перечитывания базы |
| `CRYPTO_PROVIDERS` | `kraken,coinbase` | порядок = приоритет |
| `CRYPTO_STALE_SECONDS` | `300` | порог устаревания цены |
| `CRYPTO_HEARTBEAT_SECONDS` | `0` | «пульс» для неизменившихся (0 = выкл) |

Остаются: `NOTION_TOKEN`, `CRYPTO_DATABASE_ID`, `CRYPTO_SYMBOL_FIELD`,
`CRYPTO_PRICE_FIELD`, `CRYPTO_UPDATED_FIELD`, `CRYPTO_YESTERDAY_PRICE_FIELD`,
`ENABLE_CRYPTO`, `DRY_RUN`. `COINGECKO_DEMO_API_KEY` — опционален, только для
ленивого `/coins/list`.

Устаревают и игнорируются (при задании — warning): `CRYPTO_UPDATE_SECONDS`,
`CRYPTO_CHUNK_SIZE`, `CRYPTO_CRON`.

## Зависимости

- `websocket-client` — синхронный WS-клиент (одна модель многозадачности: потоки).
- `requests` остаётся (Notion, CoinGecko `/coins/list`, валюты, привычки).

## Тестирование

Без сети и без Notion:

- `prices`: разрешение символа (пара / тикер / CoinGecko-id / алиасы / не разрешилось),
  разбор семплов сообщений Kraken и Coinbase (включая «вчера»), сравнение с epsilon,
  staleness.
- `engine`: подписка/отписка и `snapshot()` на фейковом провайдере.
- `scheduler`: строит задачи `crypto_write` и `crypto_resync`.
- Старые тесты `_fetch_markets`/`fetch_prices_from_coingecko` удаляются вместе с кодом.

## Выкат

Отдельного poll-режима не оставляем — чистая замена. Порядок:

1. Локально `DRY_RUN=true` → логи подписок и цен.
2. Деплой на Railway → контролируем, что `Last Updated` идёт, ошибок нет.
3. Старый `crypto-updater` — в запасе.

## Проверить при реализации

- Точная семантика поля «цена 24ч назад»: Kraken (`o[1]` v1 / `open` v2),
  Coinbase (`open_24h`). Зафиксировать тестами на реальных семплах.
- Полная таблица алиасов Kraken (`BTC→XBT`, `DOGE→XDG`, …).
- Наличие USDT-пар и правила выбора quote.

## Проверка (definition of done)

- `python -m pytest` — зелёный, тесты без сети.
- Локальный `DRY_RUN=true`: в логах видно подписки на пары и поступающие цены.
- `scheduler` содержит `crypto_write` и `crypto_resync`.
- На Railway: `Last Updated` в Notion обновляется; при отсутствии изменений цены
  запросов `PATCH` нет.
